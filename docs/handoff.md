# Census Bathware handoff — 25 November 2026

Implemented in the existing Next.js 16.4.6 scaffold. The repository now includes a responsive public entry, provisioned-account sign-in, explicit setup states, role-aware workspace navigation, protected searchable/filterable catalogue and variants, staff catalogue editing/archiving and private image uploads, customer/representative/offline office ordering, enquiry intake and follow-up, explicit digital invoice issuance, manual payments and cheque clearance/correction, invoice voids, assigned mobile delivery updates, customer balances, collections, monthly comparisons and representative reporting.

The application UI and transaction APIs are implemented, but a connected Supabase project is still required to use persisted business workflows. No-key mode never fabricates a successful write. Guest intake defaults off. Development `/demo` is a separate read-only fictional preview, with a Proxy-level HTTP 404 in production.

## Main folders

- `src/app`: thin public, customer and staff route groups.
- `src/features`: feature-owned views, queries, server actions, validation and accounting rules.
- `src/components/ui`, `src/lib`, `src/types`: shared accessible presentation, configuration/Supabase clients and domain types.
- `supabase`: three versioned migrations, private storage/RLS policies, constrained transaction RPCs, separate optional seed, trusted account provisioning, SQL tests and local CLI configuration.
- `tests`, `scripts`: domain/browser checks and local-only database verification runners.

## Connect after creating your project

1. `Copy-Item .env.example .env.local`; set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` from the project settings. No secret/service-role key is required.
2. Apply the three files in `supabase/migrations` in filename order using the trusted SQL Editor. Alternatively, when you choose to apply remote changes, run `supabase login`, `supabase link --project-ref YOUR_PROJECT_REF`, `supabase db push --dry-run`, then `supabase db push`. Do not load development seed into production.
3. Disable public Auth signup. Create each individual Auth user through trusted Supabase administration, with their own password. Run `supabase/provision-account.sql` with that user's existing email, full name and intended role to provision the first admin and other test users.
4. Link approved customer rows to customer profiles and create rep assignments using the provisioning script's examples. Provision separate office/accounts and delivery profiles. Optionally load `supabase/seed.sql` on a development project for fictional products/shops, then link its shops to test users.
5. Restart `npm.cmd run dev`; for production, run `npm.cmd run build` again after setting keys, then `npm.cmd start`. Sign in and perform the [connected acceptance checks](verification.md).

Full Windows commands and local database options are in [README](../README.md).
